# SIOP master amendment — NERDS USER PATH to authoritative BY-WATER course

**Date:** 18 October 2026  
**Status:** USER-REQUESTED ARCHITECTURAL AMENDMENT — recorded for incorporation into next controlling SIOP DOCX revision. Not evidence of implemented code or of completion of Stage 2.  
**Scope:** NERDS, SIOP Master §2.1–2.5, §2.8–2.10; existing Rev A file remains intact.

## Primary functional requirement

**NERDS SHALL interpret an unrestricted USER-authored USER PATH as ordered geographic voyage intent; assemble a separately versioned, evidence-supported corrected BY-WATER course; calculate authoritative WGS84 nautical miles and voyage timing from that identical assembled course geometry; and plot those same canonical vertices accurately on the Cesium GLOBE-DISPLAY Pane.** The displayed BY-WATER course must not be a cosmetically approximated or independently recomputed line.

### 1. Interpretation and state separation

- USER PATH is an arbitrary, editable WGS84 polyline with ordered stable-ID vertices. It is NOT an assertion of traversable water, roads or air.
- Preserve the exact user-intended order, optional constraints and original path revision. Do not silently move/remove waypoint intentions, substitute cities or infer a vessel-access location as a confirmed destination.
- For each adjacent waypoint pair, identify potential reachable waterways, access/transfer segments, islands, river/estuary systems and uncertainty. Ambiguous attachment, unsupported geography or disconnected basins remain explicit PROVISIONAL/UNRESOLVED, with alternatives or user decisions offered as appropriate.
- Derived course variants reference the USER PATH revision, BY-WAY/stage, profile/settings snapshots and dataset versions; recalculation never overwrites the source path.

### 2. Corrected BY-WATER course algorithm

- Identify geographic source coverage; select a coherent network for each leg and resolve both endpoints against that network; use genuine source-backed water network edges and polygon-water topology to assemble connected legs.
- Distinguish centreline networks, water-area polygons, coastlines, ocean grids, marine access and RIB/land transfer segments. Connection across data boundaries requires auditable intersecting/connected water geography; proximity, overlapping bounding boxes, polygon touches or island holes alone are not verified navigable links.
- Enforce no unsupported crossings of mapped land, islands, interior holes, blocked topology or disconnected components at the recorded source resolution.
- Assemble legs in stable USER PATH order, preserve unaffected successful legs when another is unresolved, and maintain forward/reverse consistency for equivalent constraints.
- Represent verified/calculated geometry and estimated/provisional transfers as separate typed segments; no unresolved segment is silently converted to an accepted water course.
- Preserve source identifiers, geometry origin, dataset revisions, constraints, acceptance diagnostics and per-leg status.
- Route construction must be general-purpose and dataset-driven, not tailored to the USER's historical test itineraries.

### 3. One canonical geometry for distance and globe

- Store a single authoritative ordered WGS84 course-vertex sequence (with typed segment/leg boundaries) for each derived BY-WATER course variant.
- Calculate per-leg and cumulative authoritative distance by summing **WGS84 ellipsoidal geodesics over that actual assembled geometry**; distinguish verified/calculated, provisional and unresolved totals.
- Calculate travel times and ETA from actual route distances and explicitly chosen speeds/operational modes; BY-SEA operational BYPASS defaults to USER-selected 6 kn, with NO implied power/energy model.
- The Cesium GLOBE-DISPLAY Pane MUST draw that same canonical vertex sequence, in order. No independent map-side routing, interpolated shortcuts, arbitrarily adjusted endpoint attachments or visually smoothed segments that cross land.
- Presentation-only LOD/curve simplification can reduce screen complexity solely where geographic fidelity is preserved; must not change authoritative vertices, source connections, NM or ETA. Zoom/pan/mode switching must not mutate canonical course geometry.
- Display USER PATH and calculated BY-WATER geometry independently; explicitly label accepted, provisional and unresolved parts and preserve comparison overlays.

### 4. Progressive acquisition and persistent offline reuse

- Install/retain practical worldwide baseline geography; **acquire higher-detail geographic networks and water-area data when needed** for USER-requested regions, independently of particular named regression routes.
- Coverage discovery by region/tile/basin, source/provider availability, bounded automatic online acquisition where authorised, source licence compliance, geometry integrity, atomic merge/indexing, rollback and persistent versioned offline cache.
- Prefer using already-cached data immediately; background acquisition and refinement must not block USER PATH drawing or overwrite accepted routes without explicit action.
- Once validated, new regional data may trigger a new derived course variant or user-confirmed recomputation; preserve prior result and provenance.
- Predictive prefetch for upcoming itinerary regions is optional and must respect user controls, bandwidth and acquisition policies. Offline, use prior verified data and mark coverage gaps. No AI or continuous network connection is mandatory.
- Historical named routes serve as **regression fixtures**, not as a geographically limited acquisition programme or success target.

### 5. End-to-end acceptance gates

1. **Interpretation:** User draws arbitrary route across land/water, edits/reorders, saves and reopens; original intent/stable IDs unchanged by calculation.
2. **Coverage & acquisition:** Missing network data detected with provenance; online region detail acquired/indexed; offline re-run uses persistent cache without source network access.
3. **Connected assembly:** Geographic fixture sets prove network continuity, island/hole exclusion, disconnected-water rejection, no fabricated grid/shore transitions, multi-leg independent failure handling and directional consistency.
4. **Numerical reference:** WGS84 per-segment distance and sum from stored route vertices independently compared against test oracle; provisional distances/time not silently included in verified totals.
5. **Globe correspondence:** Capture/inspect Cesium rendered route coordinates and compare with authoritative canonical route coordinates; zoom, LOD, overlay toggles and reopen cannot change NM, timing or source geometry; no drawn land shortcuts.
6. **Restart & change control:** Preserve USER PATH, calculated variants, source evidence, settings and status; acquired updates create traceable recalculations without corrupting earlier routes.
7. **Generalisation:** Procedurally generated synthetic connected/disconnected water fixtures plus geographically diverse real routes; no route-specific hardcoding to pass selected test endpoints.
